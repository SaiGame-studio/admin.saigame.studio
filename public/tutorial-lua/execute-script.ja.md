このガイドでは、内蔵スクリプトエンジンを使って戦闘の流れを管理する方法を説明します。

# 戦闘システムのスクリプトガイド

利用できるスクリプトが 1 つだけでも、このレッスンを進められます。ただし、操作が少し不便になる場合があります。

学習を進めやすくするためにスクリプト枠を追加したい場合は、Sai に相談してください。無料の追加枠を提供できる場合があります。

---

## 1. 戦闘の開始
**Battle Start** スクリプトは戦闘環境を初期化します。ひな形を読み込むには、新しいスクリプトを作成して編集モードを開き、テンプレート `#1 battle_start` を適用します。

### 主な機能
このスクリプトは主に 3 つの処理を行います。
1.  **敵の選択:** リクエストの payload に指定された `pool_key` から敵をランダムに選択します。
2.  **キャラクターの生成:** payload の `preset_id` を使ってプレイヤーキャラクターを生成します。
3.  **セッションの初期化:** `game.battle_session_create()` を使って戦闘データをサーバーのメモリに保存します。
![alt](/tutorial-lua/execute-script/step-01.png)

### リクエスト payload のパラメーター
| パラメーター | 型 | 説明 |
| :--- | :--- | :--- |
| `pool_key` | string | 敵の出現プールの識別子。 |
| `preset_id` | string | 出撃させるキャラクタープリセットの ID。 |

---

## 2. 戦闘状態
戦闘中はいつでも現在の状態を照会できます。この処理にはテンプレート `#5 battle_status` を使います。

### 実装
状態を確認するには、payload に `session_id`（Battle ID とも呼びます）を渡します。スクリプトはこれを使って、HP、ターン数、参加者などのリアルタイムデータを取得します。
![alt](/tutorial-lua/execute-script/step-02.png)

---

## 3. 戦闘ターンのロジック
このスクリプトは各戦闘ターンの実行を管理します。サンプルは基本的な攻撃効果と HP の減少を示すテンプレートです。

### 処理の流れ
* **実行:** プレイヤーと敵の間の処理を実行します。
* **勝敗条件:** どちらかの陣営が全滅するまでループを続けます。
* **カスタマイズ:** 属性の弱点、バフ、複雑な AI など、独自の仕組みに合わせてこのロジックを書き換えてください。
![alt](/tutorial-lua/execute-script/step-03.png)

> **重要:** 標準テンプレートが用途に合わない場合は、**Sai** に技術サポートを依頼してください。

---

## 4. 戦闘の終了（終了と逃走）
戦闘セッションを終了する主な方法は `battle_flee` と `battle_end` の 2 つです。

### a. 戦闘からの逃走
* **仕組み:** RNG（乱数生成器）による判定で逃走の成否を決定します。
* **結果:** 成功すると、追加の効果や報酬なしでセッションを閉じます。
![alt](/tutorial-lua/execute-script/step-04.png)

### b. 戦闘の終了
このロジックは、残っている敵の数に基づいて勝敗を処理します。
![alt](/tutorial-lua/execute-script/step-05.png)

* **敗北:** 敵が生存している状態で `battle_end` を呼ぶと発生します。
* **勝利と戦利品:** すべての敵を倒すと発生します。
    * **アイテムドロップ:** 敵またはプールに Gacha packs が割り当てられている場合、`game.open_entity_drop_packs` を呼び出します。
    * **キーの要件:** パックに特定のキーが必要な場合、戦利品を受け取るにはプレイヤーがそのキーを所有している必要があります。
    * **最適化のヒント:** **Item Generator** と連携してパック開封時の「エネルギー」消費を管理し、戦闘の過度な繰り返しを防ぎます。
* **別の流れ:** 戦闘終了時ではなく敵を倒した直後にアイテムをドロップさせたい場合は、戦利品の処理を **Battle Turn** スクリプトへ移せます。
